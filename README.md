# Совместные расходы

Приложение для совместных расходов: группы, расходы с делением поровну, долями или точными суммами, балансы «кто кому должен», минимальный набор переводов, погашения с подтверждением.

Тестовое задание (задание 6). Почему проект устроен именно так — в [docs/DECISIONS.md](docs/DECISIONS.md), ход работы во времени — в [docs/WORKLOG.md](docs/WORKLOG.md).

## Что нужно установить

- Node.js 24+
- pnpm (через corepack: `corepack enable`)
- Docker с Docker Compose

## Запуск

```bash
pnpm install
pnpm infra:up   # Postgres (порт 5433) и Mailpit (SMTP 1025, веб 8025)
pnpm dev        # сервер на :3000 и клиент на :5173
```

Откройте http://localhost:5173. Письма, которые отправляет приложение, видны в Mailpit: http://localhost:8025.

Файл `.env` не обязателен: значения по умолчанию совпадают с `docker-compose.yml`. Список переменных — в [.env.example](.env.example).

## Проверки

```bash
pnpm check      # всё сразу: типы, линт, knip, тесты (как в CI)

pnpm typecheck
pnpm lint       # ESLint, строгие правила typescript-eslint, сложность функций ≤ 10
pnpm knip       # неиспользуемые файлы, экспорты и зависимости
pnpm test       # серверные тесты ходят в Postgres, поэтому перед ними нужен pnpm infra:up
pnpm e2e        # Playwright: два браузера одновременно, свой сервер и база (нужен pnpm infra:up)
```

Те же проверки и e2e идут в CI (GitHub Actions) на каждый PR. Для e2e локально один раз: `pnpm exec playwright install chromium`.

## Как попробовать

1. Откройте http://localhost:5173, введите любую почту, например `anya@example.com`.
2. Код придёт в Mailpit: http://localhost:8025.
3. Создайте группу и позовите кого-нибудь по почте: письмо-приглашение тоже будет в Mailpit.
4. Чтобы войти вторым участником, откройте ссылку-приглашение в другом браузере или в окне инкогнито.
5. Добавьте расход кнопкой «Расход»: попробуйте 1 000 поровну на троих — лишняя копейка уйдёт тому, кто раньше вступил в группу. У второго участника балансы и переводы обновятся без перезагрузки, придёт тост.
6. Вторым участником нажмите «Отметить» у своего перевода, первым — «Деньги пришли». Баланс изменится только после подтверждения.
7. Создатель группы закрывает её в настройках: всем уходит письмо с итогом (видно в Mailpit), открывается отчёт.

## Что сознательно не делали

- **Платежи и реквизиты.** Приложение не переводит деньги, только учитывает отметки о переводах (так в брифе).
- **Офлайн-режим и очередь расходов без связи.** В ТЗ нет; при потере связи — баннер, неактивная кнопка «Расход» и черновик формы в браузере (DECISIONS, раздел 16).
- **Web Push и уведомления на телефон.** Письмами — только то, что ТЗ называет письмом; остальное — в приложении (раздел 6).
- **Несколько плательщиков одного расхода, повторяющиеся расходы, конвертация валют, распознавание чеков** — вне ТЗ, дизайнер вынес в «отложено».
- **Удаление участника и выход из группы.** В ТЗ нет; потребовали бы правил для ненулевого баланса.
- **Живое обновление чека у других участников.** Загрузка чека не создаёт события ленты (чтобы не было тоста «изменил расход» без изменения денег); другие увидят чек при следующем обновлении данных группы.

## Что сделали бы следующим заходом

- **Хранилище чеков** в объектном storage (S3-совместимом) вместо диска сервера, превью фото и сжатие.
- **Несколько экземпляров сервера:** доставка событий уже идёт через Postgres LISTEN/NOTIFY и сработает; проверка напоминаний уже защищена блокировкой и ключом письма, но её стоит вынести в отдельный процесс или cron.
- **Ограничение частоты запросов по IP** для входа и приглашений (сейчас лимиты по почте и по пользователю).
- **Выход из группы и удаление участника** с нулевым балансом.
- **Значок непрочитанного** у вкладки «Лента» и пометки «новый» у переводов (есть в макетах).
- **Наблюдаемость:** метрики очереди писем и потока событий, алерт на нарушение «сумма балансов = 0» (сейчас пишется в лог как ошибка).
- **Нагрузочный тест** потока событий и балансов на больших группах.

## Как проверяли, что это работает

- **Тесты логики денег** (`packages/shared`): деление тремя способами, лишние копейки, балансы, минимальные переводы, контрольный пример «Поездка в Казань» из брифа.
- **Серверные тесты** на настоящем Postgres: права, гонки (одновременные правки, вступления, подтверждения), конфликт версий, досылка событий после переподключения, напоминания со сдвигом времени, закрытие группы и письма.
- **E2E на Playwright**: два браузера одновременно — расход у одного виден у другого без перезагрузки, погашение с подтверждением, закрытие группы.
- **CI** на каждый PR: типы, строгий ESLint, knip, тесты, сборка, e2e.
- **Ревью кода** каждого этапа отдельной моделью и исправление найденного — в истории PR и в журнале работы.
